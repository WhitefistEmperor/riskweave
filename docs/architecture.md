# Architecture

Phase 1 is intentionally a single installable Python package with clear data boundaries:

1. `schema.py` owns strict, versionable records.
2. `scenarios.py` owns the fraud-archetype catalog and scenario assumptions.
3. `generator.py` creates legitimate traffic, hard negatives, injected rings, labels, and exports.
4. `validation.py` enforces cross-record invariants before any dataset is returned.
5. `generate.py` exposes the reproducible command-line interface.

Later phases can consume the exported contract without importing generator internals.

## Phase 2 detection path

1. `graph/builder.py` materializes entity and event nodes plus timestamped typed relationships in a
   NetworkX multidigraph.
2. `features/extractor.py` walks events in timestamp order and produces causal transaction, network, and
   temporal features. It never reads labels.
3. `baselines/` provides fixed transaction rules and a fixed static graph heuristic.
4. `models/tabular.py` provides the shared histogram-gradient-boosting implementation used for the
   transaction-only and network-aware comparison.
5. `detection/candidates.py` groups thresholded events into connected suspicious subgraphs and calculates
   members, evidence, first timestamp, risk, and exposure.
6. `evaluation/metrics.py` uses ground truth after scoring for event, ring, scenario, early-warning,
   exposure-weighted, and hard-negative evaluation.
7. `experiments/run.py` performs five leave-one-seed-out test folds. Each ML fold trains on three seeds,
   selects its threshold on a fourth seed, and evaluates once on the held-out fifth seed.

No future event is used in an event's feature row. Full graphs are used for relationship inspection and
candidate presentation; model features are generated by an independent causal stream.

## Phase 3 validation and Phase 4 analyst application

```text
Synthetic ecosystems → causal feature extraction → frozen held-out HGB scores
                                                     ↓
Chronological event prefix → candidate grouping → RingEvidenceService
                                                     ↓
                   FastAPI runtime → React/TypeScript console
                            ↓                 ↓
               bounded investigator      Cytoscape graph + timeline
                    fact selection       + benchmark/hard-negative views
```

The Phase 3 artifact supplies measured benchmark metrics, not live model outputs.
The API reproduces the seed-105 fold using the unchanged generator/detector and
keeps the trained model fixed during replay. A lock protects concurrent cold-start
dataset preparation. Scores and thresholds are converted to native Python scalars
at the API boundary to ensure real JSON serialization.

FastAPI calls the Python package directly. No database, queue, authentication stack,
microservices, or GNN is involved. React uses the existing Sites/Vinext scaffold,
shadcn primitives, Recharts, and Cytoscape. Both local dev and production-preview
servers proxy `/api` to FastAPI on 127.0.0.1:8000. The project is not hosted.

The default investigator is deterministic; an explicitly opted-in OpenAI provider
selects fact IDs under a strict schema. No model-written evidence reaches the UI.
See [investigator design](investigator-design.md) and [snapshot semantics](evidence-ui.md).

The wheel includes the measured Phase 3 JSON resource. Source checkouts load the
same artifact from `results/phase3`. Generated datasets and caches are excluded.
